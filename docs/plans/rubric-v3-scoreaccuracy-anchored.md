# 方案文档：规则层 scoreAccuracy 改造（rubric v3，issue #42）

**日期**：2026-07-09 · **状态**：已实施（OQ 全按推荐拍板，2026-07-09）· **前置**：#37 已完成、standard-15 golden 15/15 专家验证、PR-D3 K=15 基线已锁定（#52）

> **实施结果备注（2026-07-09，两轮迭代后定稿）**：
> ① 校准测量否决了四档覆盖（高质量答案覆盖率与裁判分不相关 r=0.015，28 个高质量行落在 25–50% 带）。
> ② 本方案 §五 的 D1 锚定计数**先被实现、后经对抗式设计评审 + 逐组件消融被移除**：在生产配置下（50/50 任务均有 golden）锚定装置被证明**惰性**——覆盖率地板独自完成全部真实防御（135 行无一行覆盖率 <25%）；且锚定引入了跨语言缺陷（中文垃圾 15 分反超英文垃圾 7 分、韩文/假名合法答案被饿到 7）并存在旁路（贴题标题 ±1 膨胀、as-of 日期自锚拿 30）。
> ③ **最终设计 = 地板加严（<25%→7）+ 跨文字系统弃权**（非拉丁主导答案对英文要求的覆盖率不可测：保持 v2 上限 15 并打 `cross_script_coverage_unmeasured` 标记，弃权而非猜测）。`RUBRIC_VERSION = 5-dim-cov-floor-2026-07-09`。
> ④ 影子评估：守卫集 116 行零掉落；**135/135 真实行 v2/v3 分数完全一致**（聚合逐字节恒等）→ 基线数字原样过渡到 v3，M1 验收无需重校准。F1–F4 攻击组合拳全部封死（生产配置下垃圾/标题/日期鹦鹉均 ≤7）。
> ⑤ 验收 Gate 2/3/4 未动——D3 分歧缺口被证伪为非 stuffing 通路（实为"切题但语义肤浅"，关键词层不可评，归 min(judge) 管辖），该目标按错误归因撤销。详见 PR-D3 报告附录 A 与 PR #53。
**一句话**：把规则层 A 维度（30 分）从"数据密度启发式"重构为"requirement 锚定计数 + 分档覆盖"，使规则层单独可信，并在 **M1 降本验收之前**冻结 rubric v3。

## 一、目标

1. **堵住 digit-stuffing 漏洞**：无关文本掺 ~15 个数字即可在规则层拿 A=15–30（`test/grader-degenerate.test.mjs:94` 以"固化测试"形式记录在案）。改造后同一输入 **A ≤ 7**。
2. **消除规则层对 baseline 的系统性偏袒**：D3 实测规则层平均高估 baseline +6.8 分、cli +5.7、mcp +4.0——差异性偏松使 **rule lift 被低估 +1.1（cli）/ +2.8（mcp）**。改造后三个 cell 的 mean(rule−judge) 收敛。
3. **让 `--no-judge` 规则单口径从"带警告的不设防"变为"可独立作快速回归门"**：目前该模式唯一保护是 `scoring_guards.rule_only_unguarded` 警告标志，无实质防御。
4. **在 M1 验收窗口前冻结 rubric v3**，保证 M1 前后对照用同一把尺子。

**不改的东西**（范围收敛）：B/C/D/E 四个维度、GLM 裁判、`min(rule, judge)` 合成、硬失败类（prompt_echo / empty_result 等）、golden 规格文件——全部不动。只动 `scoreAccuracy`（`src/grader.mjs:46-104`）及其测试。

## 二、必要性（为什么必须做、为什么是现在）

**N1 · 漏洞已从"文档记录"变成"量产实测"。** M0 时这是 degenerate 测试套件里的已知缺口；D3 的 135 行里分歧审计抓到 **21 行 flag，20 行是规则高估，最大 +63/+50/+36 分**，集中在堆数字任务（btc/bnb 波动、fx-em-stress、年报审计）——真实 agent 产出（不是构造攻击）已经在触发这条通路。

**N2 · 偏差方向恰好损害我们自己的结论。** 规则层最偏松的是 baseline（+6.8 vs cli +5.7 / mcp +4.0）。这意味着我们对外的保守下限口径（rule lift +8.2/+7.2）**低估了 QVeris 的真实差距约 1.1/2.8 分**。测量误差不可怕，方向性偏差损害可信度——"经得起检验的评测"不能带着已知的方向性偏差进 M1。

**N3 · 时机是单向门：rubric 必须在 M1 验收前冻结。** 我们自己的测量保真度结论（M0，写进了论文）：**评分定义变更对判决的影响是采样噪声的 1.2–1.4 倍**。若 M1 落地后再改 rubric，等于验收中途换尺子，服务侧有充分理由质疑"画像翻正是评分 artifact"。v0.2 评审正是以"循环论证"暂停过验收目标——同一逻辑，这次提前自觉处理。M1 窗口 ≈2 周，本改造 3–5 天，窗口刚好。

**N4 · 解锁条件本周刚刚齐备。** #42 自己写明的两个前置：① #37 golden 验证重写完成（✅）；② requirement 措辞需 matcher-reliable——standard-15 现在 15/15 专家验证，措辞经过两轮专家修订（✅ 2026-07-08）。且 D3 批次提供了 135 行带真实裁判分的校准集——**三个月内不会有更好的动工条件**。

**N5 · 外部可防御性。** 这是 τ-bench 空答案缺陷（ABC audit, arXiv:2507.02825）的同类问题高一层的版本。论文（#40）和对外引用都指向这套 harness；已知同类缺陷不修，审稿人/客户按图索骥即可复现攻击。

## 三、价值与 ROI

### 直接收益（量化）

| 收益 | 量化 | 受益方 |
|---|---|---|
| **M1 快速回归口径可信** | judged 全量回归 = 135 次 GLM 调用 ≈ 70 分钟你的终端时间/轮；规则单口径 = **0 成本、秒级**。M1 灰度（5%→50%→100%，参考 quaestio#832 惯例）意味着多轮回归——v3 让服务侧自助跑规则层预门，只在预门通过后才烧一次 judged 终审 | 服务侧 + 你 |
| **下限口径纠偏** | rule lift +8.2→约 +9.3（cli）、+7.2→约 +10.0（mcp）；对外引用的保守数字不再自伤 | 产品叙事 |
| **分歧队列降噪** | 21 行 flag 中 20 行规则高估——改造后预期 flag 数减半以上，#37 裁定人工量同步下降 | harness 运维 |
| **攻击面关闭** | degenerate 套件的 digit-stuffing 从"documented gap"翻转为"capped at A≤7"（固化测试同 PR 内翻转删除，测试注释已预写此流程） | 论文 #40 / 对外可信度 |

### 成本

- **工程**：3–5 天（启发式改造 ~1 天、D3 校准与切点标定 ~1 天、测试改造 ~0.5 天、双 rubric 对照重评与报告 ~1 天、评审缓冲）。
- **重评成本**：**接近零**。规则层重评离线免费；judged 主口径**不需要重跑 GLM**——135 行的 `llm_judge` 结果已存盘，v3 的 `min(rule_v3, judge_stored)` 可离线重组（方法学上这反而更优：裁判严格恒定，纯隔离定义变更效应，与 PR#48 重评隔离协议一致）。
- **风险成本**：误伤合法答案（见 §六 风险与对策——用 D3 的 135 行做影子评估，judge≥0.8 的行作"合法答案守卫集"）。

### ROI 结论

一次性 3–5 天投入，换取：M1 验收期每轮回归节省 ~70 分钟人工 + 消除下限口径 1–3 分方向性偏差 + 关闭已发表文献同类攻击面。**这是 M1 前 harness 侧性价比最高的一件事**——且过了 M1 窗口，价值折半（尺子中途换不得，只能等 M2）。

## 四、现状代码剖析（问题的精确位置）

`src/grader.mjs:46-104`，现行逻辑三段：

```
dataRichness = count(数字) + 2·count(日期) + count(命名实体)     // :60-64
coverageCap  = (requirement 命中率 < 25%) ? 15 : 30              // :77-80 平顶
无 expected_facts 分支：richness ≥15 → min(30, cap)；≥5 → min(15, cap)   // :100-103
有 expected_facts 分支：命中率 ≥0.6→30 / ≥0.2→15 / richness≥10 兜底 15   // :86-97
```

三个缺陷：
1. **数字不问出处**：`dataRichness` 只数模式不问相关性——公交车客流量和 CPI 同权（degenerate 测试的攻击面）。
2. **覆盖度只是平顶**：<25% 封 15，≥25% 即放行到 30——29% 覆盖与 100% 覆盖在 cap 上无差别。当时的理由（`:66-75` 校准注记）是 matcher 在合法答案上噪声太大（0.29–1.00 与裁判分不相关）——**该前提已失效**：措辞已专家验证，且注记自己写明"golden 验证重写后升级为分档"。
3. **兜底通路穿透**：无 facts 任务（50 题里占多数）走纯 richness 通路，stuffing 直达 A=15–30。

`requirementSatisfied`（`:813+`）三级匹配（整句包含 → 60% token 命中 → 概念正则），是分档覆盖的地基——v3 动工第一步是**在 D3 数据上重测它的噪声**（专家措辞版），决定分档能承载多少权重。

## 五、方案设计

采纳 #42 候选方向 1+2 组合，方向 3（VeriScore 式声明抽取）推迟到 v4（引入 LLM 会破坏规则层"免费快速"属性）：

### D1 · Requirement 锚定计数（治缺陷 1）

数字/日期/实体**只在 requirement 命中点附近计数**：以每个 `requirementSatisfied` 命中位置为锚，仅统计锚点 ±W 字符窗口内的数据信号。垃圾数字没有锚点 → richness ≈ 0 → A=0。合法答案的数据天然聚集在要点周围 → 计数基本不变。

### D2 · 分档覆盖替代平顶（治缺陷 2）

```
覆盖率 < 25%   → A ≤ 7    （现为 ≤15）
25% – 50%      → A ≤ 15
50% – 75%      → A ≤ 22
≥ 75%          → A ≤ 30   （不变）
```
切点在 D3 批次上校准后定稿（§七 流程第 2 步）；若重测的 matcher 噪声仍高，退守保守两档（<25%→7、<50%→15，上半段不分档）。

### D3 · expected_facts 分支收紧（治缺陷 3 的残留）

facts 命中率 <0.2 时的 richness 兜底（`:97`）改为锚定 richness——与 D1 同一把尺，穿透通路关闭。

**合成不变**：`min(rule, judge)`、裁判、B–E 维度全部原样。v3 是纯 A 维度手术。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 误伤合法答案（锚定窗口太紧 / 分档太狠） | **影子评估**：v3 在 D3 全部 135 行上跑一遍，`judge ≥ 0.8` 的行为守卫集——任何守卫行因 v3 从 pass 掉到 fail 即回炉调参。分歧队列里唯一的 judge_overrates 行（半导体出口管制，−22）作为定向哨兵 |
| matcher 噪声仍高，分档不可靠 | 动工第一步先重测（专家措辞 × D3 答案）；噪声仍高则退守两档方案，D1 锚定照做（锚定不依赖分档粒度） |
| v3 改变已锁定基线的叙事 | PR-D3 报告保留 v2 记录不动，**附录**发布 v3 双口径对照（v2/v3 × rule/judged 四格）；M1 验收前后统一用 v3。对外引用规则同 golden 世代标注惯例 |
| 中文文本的正则覆盖不足（数字/日期模式偏英文） | 校准集中含中文任务产出（A股/比亚迪等），影子评估天然覆盖；发现缺口在 v3 内一并补模式 |

## 七、实施流程与验收

**流程**：① matcher 噪声重测（D3 × 专家措辞）→ ② D1+D2+D3 实现，切点/窗口在 D3 上校准 → ③ 测试改造（degenerate 固化测试翻转删除 + 新增锚定/分档用例）→ ④ D3 批次 v2/v3 双口径重评（规则离线 + judge 存盘重组）→ ⑤ 对照报告 + `RUBRIC_VERSION` 升版 → ⑥ PR + 评审。

**验收标准**：
1. digit-stuffing 用例规则层 **A ≤ 7**（固化测试翻转，同 PR 删除）；
2. 守卫集（D3 中 judge≥0.8 的行）**零行**因 v3 从 pass 掉 fail；
3. 三 cell 的 mean(rule−judge)：baseline 6.8 → **≤3**，且对 baseline 的差异性偏松（现 +1.1/+2.8）→ **≈0**；
4. 分歧 flag 数 21 → **≤10**；
5. 全部测试绿；golden 文件零改动。
